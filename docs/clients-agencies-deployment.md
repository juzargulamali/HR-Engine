What the migration adds (and why nothing smaller works): `crm_organisations.roles` (one record, several roles; `kind` stays and is derived), `country_code`, `website`, `website_domain`; the per-company table `crm_account_profiles` (account owner, lead source, exhibition); and six functions: `crm_can_edit_organisation`, `crm_create_organisation_profile`, `crm_update_organisation`, `crm_save_account_profile`, `crm_assign_account_owner`, `crm_reassign_follow_up`. It also re-defines `crm_create_organisation` (same signature) so organisations made the old way record their role.

The corrections add (all in the same file): **changing** — the database import function `crm_import_apply` with helpers and `crm_import_fingerprints`, the table `crm_import_batches` (no policy, no direct access), the unique index `uq_crm_contacts_org_email`; the trigger `crm_opportunities_party_roles` (an inquiry's agency must hold the agency role and its end client the end-client or direct-client role, checked on create and when the field changes); `crm_follow_ups.opportunity_id` made nullable plus `organisation_id`, the function `crm_create_account_follow_up`, and `crm_complete_follow_up`, `crm_reschedule_follow_up`, `crm_cancel_follow_up`, `crm_reassign_follow_up` with one added branch each. **Read-only** — pack files 00, 05 and 20 only select; 90 (rollback) writes.

**Pre-inquiry outreach (section 8, same file, same pack).** **Changing** — two new tables (`crm_outreach`, `crm_outreach_events`, SELECT policy only, writes function-only, the history refuses update and delete) and six functions (`crm_assign_outreach`, `crm_outreach_log`, `crm_outreach_set_next`, `crm_outreach_set_status`, `crm_outreach_link_inquiry`, helper `crm_outreach_acting_on`) plus the guard trigger function. It changes nothing that exists (no existing function, table or policy is touched), so the preservation check 05 needs no new difference. **Read-only** — pack file 20 now also checks the two tables (RLS on, SELECT only, anonymous nothing), the append-only trigger, the one-open-outreach index, the assign right and eligible-person check, the narrow read policy, that no outreach function touches an account owner, and (check 27) that a new activity's outcome must fit its kind (call, e-mail, meeting lists) while the stored-outcome constraint still allows every value of the original single list; file 00 (preflight) is unchanged. Rollback 90 (**writes**) also drops the outreach functions and tables and deletes all outreach and its history: export `crm_outreach` and `crm_outreach_events` first.

No access is widened. Reads of the new table need a CRM grant for that company. Editing an organisation follows the existing contact rule; assigning an account owner needs the existing `assign_owner` capability (founder implies it) in that company. Being account owner, follow-up assignee or outreach assignee confers no extra right; assigning outreach uses the same `assign_owner` capability, and outreach is readable only by its assignee and by `assign_owner` holders of that company. Tests: `packages/rls-tests/test/crm-clients-agencies.rls.test.ts`. Control reference: `docs/enginious-os/modules/sales-clients-and-agencies.md`.

What to expect after applying: nothing visible changes for existing inquiries (the role check applies only when a field is set or changed); the import confirm applies in one database call and refuses a stale preview; an account with no inquiry can take a dated follow-up. Account follow-ups do not generate reminders or e-mails (reminders are tied to an inquiry).
