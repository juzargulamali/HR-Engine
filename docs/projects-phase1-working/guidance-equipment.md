## Name the Project Manager for a handover
- id: projects-assign-project-manager
- area: projects
- status: published
- keywords: assign project manager; name the project manager; change project manager; who assigns the PM; handover waiting for a project manager; founder; PM assignment; choose a PM; handover submitted by sales
- links: Handovers -> /projects/handovers; Projects -> /projects
- screens: /projects/handovers

When Sales submits a handover, a founder, or someone a founder gave PM assignment to, names the Project Manager. Those handovers are listed under Waiting for a Project Manager to be named, the longest wait first. Only people with Projects access in that company can be chosen. The person you name is told, and then accepts the handover or asks Sales a question. You can change the Project Manager until the handover is accepted.

1. Open Handovers under Projects, or open the handover from My Day.
2. Read the brief: agreed scope, site and dates, equipment, dependencies and risks.
3. Choose a person under Project Manager and press Assign Project Manager.
4. To name someone else later, choose them and press Change Project Manager.
5. If the person is not in the list, a founder gives them Projects access first.

## Request equipment for a project
- id: projects-equipment-request
- area: projects
- status: published
- keywords: equipment request; request equipment; new equipment request; submit to the warehouse; equipment draft; imported from the sales handover; technology template; planning dates; add an item; cancel request; substitute; need to buy or rent; still out; waiting for the warehouse
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/equipment

The Project Manager asks the warehouse for equipment on the project's Equipment tab. A project that came from Sales starts with a draft marked Imported from the Sales handover. A request is a Draft until you press Submit to the warehouse; submitting reserves nothing, the warehouse reserves from stock. Then it reads Waiting for the warehouse, Being prepared, All dispatched and Closed. Other team members can read the tab but not change it.

1. Open the project, then Equipment. Open the draft, or press New equipment request and Create draft.
2. Under Planning dates set at least a start and an end, then press Save the dates.
3. Use Add an item or Add from a technology template; change a line under More.
4. Press Submit to the warehouse. If something is missing, the page says what.
5. Afterwards watch Reserved and Not covered yet; use Accept or decline for a proposed substitute, and Need to buy or rent for a shortage.

## Dispatch and return notes on a project
- id: projects-equipment-notes
- area: projects
- status: published
- keywords: dispatch note; return checklist; return note; acknowledge; confirm this list; report a difference; dispatch waiting for you; returned please confirm; equipment still out; download PDF; equipment not returned; finished project equipment
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/equipment

Where your company uses dispatch notes, each time the warehouse sends equipment to a project or receives it back, a numbered note appears under Dispatch & return notes on the Equipment tab. The Project Manager acknowledges it or reports a difference; nothing waits for the answer and no equipment moves because of it. Equipment still out lists what has not come back. Completing a project does not return equipment: only the warehouse records a return.

1. Open the note from My Day, or open the project, then Equipment.
2. Read the lines. Press Acknowledge for a dispatch, or Confirm this list for a return.
3. If something differs, press Report a difference, tick the lines, choose what is different and press Send to the warehouse.
4. The warehouse answers it. Withdraw the report takes your report back.
5. Use Download PDF or Open to print for a copy of the note.

## From a won job to a finished project: who does what
- id: projects-won-job-to-finished
- area: projects
- status: published
- keywords: who does what; won job; handover to project; project workflow; next step; sales to projects; warehouse; dispatch; returns; complete project; start to finish; whose turn
- links: Handovers -> /projects/handovers; Projects -> /projects; My Work -> /projects/work; Requests -> /inventory/requests
- screens: /projects/handovers; /projects/[id]/work; /projects/[id]/equipment

A won job passes from Sales to a founder, to the Project Manager, to the warehouse and back. Sales submits the handover. A founder names the Project Manager, who accepts it: that creates the project and opens its Work page. The Project Manager adds the team, plans the tasks and submits the equipment request. The warehouse reserves, sends out and later records what came back. Completing the project does not return equipment.

1. Sales: confirm the enquiry as won, then prepare and submit the handover.
2. Founder: open Handovers and press Assign Project Manager.
3. Project Manager: press Accept handover, add people under Manage project, People & access, and add tasks on Work. Everyone added is in the project's Chat.
4. Project Manager: on Equipment, check the draft and press Submit to the warehouse; acknowledge the dispatch note when it comes.
5. Project Manager: use Manage project, Complete project when the work is done. Warehouse: record the returns; the Project Manager confirms the return list.
