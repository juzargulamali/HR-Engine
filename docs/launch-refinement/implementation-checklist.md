# ENGINIOUS OS: implementation checklist

**Status:** checklist for approval. **Nothing is implemented.** No migration, hosted SQL, job activation, access change or Production change has been made.
**Basis:** the launch-refinement specification (`specification.md`, same folder) on `main` at `76c121b`. This checklist does **not** repeat the audit: every item points to its register ID (`D-` defect, `U-` usability, `N-` new functionality) where the full entry, roles, data sources and further acceptance checks live.
**Revision 2 (2 Nov 2026):** the budget-notification finding is corrected (item **A8**): the notices *are* created for Finance and executive approvers; what fails is that a Finance-only person who is not on the project cannot see them.

## How to use this checklist

| Column | Meaning |
|---|---|
| **ID** | Checklist item and its register entry. Work packages (WP) match Section 1.3 of the specification. |
| **Evidence / reproduction** | Where it is in the code, and how to reproduce it on the **local throwaway stack** (never hosted). *Code* = confirmed by reading code/SQL, not run. Items marked *runtime check* need to be reproduced locally before the fix. |
| **Correction** | The smallest change that removes the defect without touching a protected rule. |
| **Migration** | **None** = no database change. **Yes** = a new or replaced database object, applied only by the owner through the existing owner-run pack (preflight, verify, rollback). |
| **Acceptance test** | What must be observed, including the failure and permission case. |

**Rules for every item**
1. A failed read must say "could not load" (never empty, zero, "nothing waiting" or "no access").
2. Any new restriction is enforced in the database, with a test that a refused role is refused when calling it directly.
3. No stock, balance or approval changes as a side effect.
4. Every migration ships with RLS tests (new rule plus a preservation check), a verify script and a rollback note; the owner applies it.
5. Both themes and phone width are checked for every new screen.
