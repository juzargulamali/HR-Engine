# Sales: Estimates & Quotations (part 1: builder, issue, frozen snapshot; part 2: PDF and Excel export)

Status: in draft PR on branch `feat/estimates-quotations` (not merged, no hosted SQL run). Part 2 (export) is the last section. Conventions as in `../README.md`: every claim cites a source; who "can use it" is what the screen offers, the named database function is the real gate and repeats the check. Migration: `supabase/migrations/20261220000100_crm_estimates_quotations.sql`; deployment: `docs/estimates-quotations-deployment.md`.

## 1. Model and decisions

| Topic | What was built | Source |
|---|---|---|
| One record, not two | Every quotation IS a `crm_proposals` row (version, status `draft/sent/superseded/accepted`, `sent_on`, approval link). `crm_quotations` is its 1:1 extension. A proposal row holds only a note and a file, so it cannot hold sections, lines, currency, VAT, bill-to, milestones or terms | migration header; `crm_quote_create` |
| Authorised | The enquiry owner or a Sales founder (`crm_require_owner_or_founder`, the existing proposal rule), company scoped (`crm_has_access`). Other Sales grant holders can read, not change | `crm_quote_load_editable` |
| Status shown | Draft, Draft awaiting approval, Issued, Superseded (derived: `issued_at`, proposal status, a pending approval). "Recorded as sent" / "Accepted" stay the existing manual proposal facts | `lib/crm/quotations/model.ts` `quotationState` |
| Withdraw / cancel | The existing model: "Mark superseded" on Proposals & files (`crm_set_proposal_status`). The snapshot is never altered | proposal status model |
| Approval (bound to the exact version) | Existing commercial approval, now tied to a content hash (`crm_quote_content_hash`: everything client-facing, never internal notes). Policy `required`: request = `crm_quote_request_approval` (records the hash; withdraws a waiting request for an older version); decide = `crm_quote_decide_approval` from the "Review for approval" panel on the quotation page, which carries the hash the screen was rendered with. **Stale screen:** if Sales edits after the founder opened the page, approving is refused ("This quotation changed after you opened it. Review the latest version; a fresh approval request is needed") and nothing is recorded; the generic decide path cannot approve a quotation approval (trigger). Issue needs an approval whose bound hash equals the current hash, so an edit after the request or after the approval needs a fresh request. `not_required` and `not_configured` do not gate issuing. `crm_request_approval` / `crm_decide_approval` are unchanged for other proposals | `crm_quote_request_approval`, `crm_quote_decide_approval`, `crm_quote_issue`, `crm_approval_quote_guard`; RLS "approval is bound to the exact version reviewed" (5 tests); browser flow |
| Numbering | Sections are numbered 1, 2, 3 and items `1.1, 1.2, 2.1` (one function, `lineDisplayNumber` in `packages/domain`; the SQL snapshot mirrors it; builder, snapshot, PDF and XLSX show the same). Every item belongs to a section, so there are no unsectioned items. The snapshot stores the display numbers as at issue | `packages/domain/src/quotations.ts`; domain test; RLS "numbers sections 1, 2 and lines 1.1 ..." |
| Exclusions | A separate list on the quotation (`crm_quotations.exclusions`, title + text), edited in "Payment milestones and terms", printed as its own block before Terms and conditions. Empty by default: nothing is seeded and the six working-draft terms clauses are unchanged | `crm_quote_save_header`; RLS "Exclusions are their own block" |
| Pinned logo and pictures | At issue the server copies the company logo and each item picture to immutable copies owned by the revision (bucket `quotation-assets`, path carries the SHA-256) and the snapshot records only those paths and hashes. A later logo or picture change cannot alter an issued export; exports check the hash before embedding. **Verified on an isolated local Supabase stack with real Storage (`f90c915`); hosted V2 not yet verified**. Unit tests still use a storage seam | `lib/crm/quotations/pin-assets.ts`, `crm_quote_issue(p_proposal, p_assets)`, `crm_quote_check_asset`; RLS "pictures", "issuer details"; `export.test.tsx` |
| Calculation | One function, exact decimals: line = round-half-up(qty x unit price) to 2 decimals; VAT per line = round-half-up(line x rate / 100); subtotals and totals are sums of rounded lines; Out of scope and "not chosen" add no VAT; negative refused. TypeScript and SQL are proved identical by an RLS test | `packages/domain/src/quotations.ts` `calculateQuotation`; `crm_quote_build_content` |
| Currency and VAT | One currency per quotation from AED, SAR, PLN, EUR, USD, chosen explicitly. VAT chosen explicitly from the company's list (seeded Out of scope, 0%, 5%, 15%, 23%; none is a default); a per-item override is allowed. Both are required at issue, optional on a draft. Nothing is inferred from a country | `crm_quote_save_header`, `crm_quote_vat_choices` |
| Internal notes | Only `crm_quotations.internal_notes`. Never copied to the snapshot and never to be read by an export. No costing, supplier price or margin exists in v1 | `crm_quote_build_content` (does not select it); RLS test |
| Bill-to | Chosen explicitly per quotation: an organisation of the enquiry (agency or end client) or any other organisation. Name, place (the only address field organisations have), country, VAT / TRN and trade licence are read live while draft and frozen at issue | `crm_quote_build_content` |
| Issuer | Read from the company's own record (`companies`): legal name, TRN, address, phone, email, website, logo path. At issue the legal name must be non-blank; the TRN is shown when present; nothing else is required | `crm_quote_issue` |
| Revisions | "Create revision" copies an issued quotation to a new draft (same reference, revision + 1, linked). Issuing it marks earlier draft or sent revisions `superseded` (an `accepted` one is left alone); the old snapshot is untouched | `crm_quote_create_revision` |
| VAT default | No VAT choice is pre-selected on a new quotation (the seeded list offers Out of scope, 0%, 5%, 15%, 23% but Sales must choose; nothing is copied from any sample workbook) | `crm_quote_create`; RLS "creates a draft ..." asserts all VAT columns are null |
| Reference | `QUO-<company reference code>-<year>-<nnnn>` from `crm_quote_counters` (same pattern as the enquiry counter), assigned when the draft is created | `crm_quote_create` |

### 2.5 Frozen snapshot (the seam for part 2)

`crm_quotation_snapshots.content` (type `QuotationSnapshot`, `packages/domain/src/quotations.ts`): `schema_version`, `reference`, `revision`, `issue_date`, `validity_date`, `enquiry`, `issuer` (incl. `logo`: pinned asset in `quotation-assets` with SHA-256), `bill_to`, `currency`, `minor_units`, `vat`, `sections[]` (number, title) `.lines[]` (display number `1.1`, description, `image`: pinned asset with SHA-256, unit, quantity, unit price, per-line VAT, net, VAT, gross), subtotals, `totals`, `milestones` (with computed amounts), `exclusions`, `terms`. Guard triggers refuse any change, even by a table owner (`crm_quotation_frozen`). Read it through `loadQuotation(...).snapshot` (`apps/web/src/lib/crm/quotations/data.ts`).

## 3. Not covered in part 1 (stated, not hidden)

No costing, supplier price, margin or discount (a discount line is deferred by the owner). No sending of a quotation. Moving an item to another section: delete and re-add (reorder works inside a section; deferred by the owner). Hiding or editing an existing VAT choice has a database function but no screen (only Add; deferred by the owner). The line picture upload cannot be driven on the local stack (no object storage); its checks are covered by unit and RLS tests. "Record as sent" on Proposals & files is not blocked for a draft estimate (the existing rule is unchanged).

## Export (part 2)

Source of truth: ONE document model (`lib/crm/quotations/export/doc-model.ts`, `QuotationDocModel`) feeds both files. An **issued** revision (current or superseded) is built ONLY from its frozen snapshot (never from live account, company or template rows; if the snapshot cannot be read there is no file, 503). A **draft** is built from the live draft through the same `calculateQuotation` and is marked **DRAFT** everywhere. The model has no field for internal notes, costs, margin or supplier prices, so an export cannot print them. Nothing is stored and nothing is sent: staff download the files and share them themselves (no automatic email in v1).

## Open owner decisions

* Discount line: deferred (not added).
* Moving an item between sections: deferred (delete and re-add).
* VAT choice management screen (edit, hide): deferred; only Add exists.
* Exclusions and Terms: now separate blocks; the six terms clauses keep their "working draft, pending legal review" label and no wording was seeded into Exclusions. The label is printed under the Terms heading in both exports so unreviewed terms are never sent unknowingly; the owner may prefer to hide it once legal has reviewed them.
* Numbering `1.1` style: decided (done). Assumptions are not a separate block (they are written as terms clauses or exclusions as before).
* Automatic email of a quotation: not in v1.
