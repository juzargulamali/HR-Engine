## 1. The goal in one workflow
When a show is coming up a salesperson opens the event, sees which clients exhibited before, which agency built each stand in each year, and which agencies to contact, with each agency's shared **Outreach priority**, then opens the account to start outreach or a follow-up (the existing Outreach and Follow-up workflow). At the show, **Record an observation** takes the edition, the exhibitor and the agency (or "Agency unknown") on a phone, with no enquiry.

## 2. What is shared and what stays company-scoped
| Shared by every person with a Sales grant, in any company | Company-scoped (unchanged) |
|---|---|
| Accounts (organisations and contacts; `crm_organisations`, read with `crm_has_any_access()`), the **Outreach priority** (`crm_organisations.outreach_priority`), events, editions, observations | Enquiries and everything on them (`crm_opportunities`, read with `crm_has_access(company_id)`), estimates, follow-ups, outreach assignments, **per-company account fields** (account owner, lead source, exhibition: `crm_account_profiles`) |

The link between the two lives on the enquiry (`crm_opportunities.event_edition_id`), so an edition's figures are computed from the enquiries **the viewer's own session can read**. An enquiry of a company the viewer has no grant for is invisible to them and contributes nothing to a figure or a drill-down (RLS test `crm-events-outreach.rls.test.ts`, browser flow step 3).

### 3.4 Import events (`/sales/events/import`, `apps/web/src/app/(app)/sales/events/import/`)
| Step / control | What it does | Behind it |
|---|---|---|
| **Download template** | A blank `.xlsx`: one row per **edition**, columns **Event name, Country, City, Venue, Start date, End date** (date columns formatted YYYY-MM-DD) plus an Instructions sheet. Generated on request, nothing stored | `GET /api/sales/events/import/template`, `buildEventsTemplate` |
| Upload (.xlsx or .csv, 4 MB, 2000 rows) | **Required:** Event name, Country, Start date, End date. Dates: `YYYY-MM-DD`, a native Excel date cell, or an Excel serial number; anything else is refused with the cell's value ("use YYYY-MM-DD"). Country: a name or two-letter code (recognised list, `UK` = GB). End before start, a year outside 2000-2100, over-long text are refused. The .xlsx is opened with the Clients & Agencies import's safety checks (no macros, zip-bomb limits, formulas never run); a CSV may use commas, semicolons or tabs and a BOM. Formula-neutralised cells (`'=`) are read back as typed. Only events and editions: no observation, agency or enquiry data, no export, no automatic linking of enquiries | `parseEventsFile` (`lib/crm/events/import/parse.ts`), `readImportSheet` (reused) |
| **Preview** (nothing is saved) | Counts and one entry per row with its **row number** (header = row 1), marked **New event** (creates the event and its edition), **Adds an edition** (to an existing event, or to an event created by an earlier row of the same file), **Already present** (skipped) or **Needs correction** (invalid / conflict / ambiguous / review) with the specific reason. Rows that need correction are listed first and open | `POST /api/sales/events/import` mode=preview; the database classifies every row (`crm_import_events` with `p_apply = false`) |
| **Confirm** | Enabled only when **no row needs correcting** and at least one edition would be added. Sends the count the person saw; the server re-reads the file, re-classifies and writes **all rows in one transaction or none**. If the calendar changed since the preview (different count, a new conflict, a duplicate-key race) nothing is saved and a fresh preview is asked for. Result: events added, editions added, rows skipped as already present | mode=confirm; `crm_import_events` with `p_apply = true`, `p_expect` |
| Rules (database, the same for preview and save) | **Event** = the same name ignoring case and punctuation as a **live** event (the existing `name_key` rule); several rows of one event add editions under ONE event (the first row's spelling names it). **Never merged otherwise.** A name that matches only an **archived** event is flagged (never reopened). A short name contained in two or more live events ("Gulf" in "Gulf Mega Expo" and "Gulf Mini Expo") is **ambiguous**; exactly one similar event is noted ("kept as a separate new event"), not blocked. **Edition** = (event, start date), the existing identity rule (no simultaneous editions of one event): same start and end = **already present** ONLY when the **country, city and venue the row states also match** the recorded edition after normalisation (case, spaces and punctuation ignored; a blank city or venue in the row states nothing; a stated value must equal the recorded one, a recorded blank counts as different). **If the dates match but country, city or venue differs (for example the UAE edition recorded and a KSA row), the row is flagged for review ("not treated as already present", with what differs) and blocks the confirmation**; nothing is overwritten and nothing in the file is written. Same start with a different end, or overlapping dates = **conflict** (dates are never overwritten); an archived edition on that start date is flagged (never reopened); repeats inside the file are tested the same way (identical = clean repeat, a different country / city / venue = review naming the earlier row). Re-uploading the same file adds nothing | `crm_import_events` |
| Permission and protection | Any Sales grant; signed out / no grant refused before the file is read and again by the database. Validation, duplicate protection and the one-transaction write are all in the database function, behind a per-import advisory lock; a forged request cannot bypass them | `runEventsImport`, `crm_import_events` |

### 3.3 Record an observation (dialog, built for a phone)
Fields: **Edition** (native select), **Exhibitor / client** (search-as-you-type over the shared directory), What did you see (**Exhibited** / **Did not exhibit**), **Agency** (search over accounts recorded as agencies) or tick **Agency unknown**, optional **Stand number**, **Agency role** (Stand builder, Stand design, AV / technology, Fabrication, Other), a **Confirmed** tick (unticked = Unverified) and a note. It creates no enquiry and needs none. Did not exhibit takes no agency, stand or role. Typing in a search field never selects or creates an account: choose a match, or add the account first (the empty state links to Clients & Agencies). `saveObservation` -> `crm_record_observation` / `crm_update_observation`; the shape is enforced again by the table CHECK (`crm_event_observations_shape`) and the agency must hold the Agency role (`crm_observation_check`). Tests: `actions/events.test.ts`, RLS "observations", flow step 4 (on a 390 x 844 touch viewport).

## 4. Outreach priority
One shared value per account, **1 to 5 (5 highest) or Unrated**, the team's own rating of who to approach, not a review score. It is shown in the Clients & Agencies table (column "Outreach priority", sortable, highest first, **Unrated always last**), filterable (Any, 5 only, 4 and above, 3 and above, Any rating, Unrated), set on the account page ("Outreach priority (shared)") and on each lead of an event. Setting it saves at once; who set it and when is stored. **Any Sales grant may set it** (wider than the "edit a shared organisation" rule, a decision recorded in `docs/events-outreach-deployment.md`). `setOutreachPriority` -> `crm_set_outreach_priority`; tests `directory.test.ts`, `actions/events.test.ts`, RLS "shared outreach priority".
