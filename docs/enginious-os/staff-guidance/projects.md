# Staff guidance: Projects & Tasks

Approved, staff-facing guidance. JARVIS answers "how do I" questions from the topics below that are marked `published` (see [README](./README.md)).

## Projects and tasks
- id: projects-where
- area: projects
- status: published
- keywords: project; projects; task; tasks; my work; my tasks; milestone; project calendar; project plan; handovers; new project
- links: My Work -> /projects/work; Projects -> /projects; Project calendar -> /projects/calendar
- screens: /projects; /projects/work; /projects/calendar

Your own tasks are under My Work; the Projects page lists the projects you can see. A project opens on Work, with Timeline and Equipment beside it; the rest is under Manage project. The project's conversation is its group in Chat. JARVIS cannot read or change projects yet: use the screens.

1. Open My Work for your tasks, the reviews waiting for you and the blockers you can clear.
2. Open Projects for the directory and choose a project. It opens on Work.
3. Read What needs doing at the top of Work: it lists what needs you and what is waiting on someone else.

## My tasks in projects: My Work
- id: projects-my-work
- area: projects
- status: published
- keywords: my work; my tasks; waiting for my review; review queue; blockers; blocked task; who can unblock; sent for review; overdue task; start a task; submit for review; mark done
- links: My Work -> /projects/work
- screens: /projects/work

My Work keeps three things apart: My tasks (work you must do), Waiting for my review (work others sent you to accept or send back) and Blockers I can help clear (blocked tasks that name you, or that nobody is named on in a project you manage). Work you sent for review is listed separately as waiting on someone else. A task opens in a panel beside the list, so your search, filters and view stay.

1. Open My Work and choose My tasks, Waiting for my review or Blockers I can help clear.
2. Open a task. The top says where it stands, when it is due, what blocks it and who can unblock it.
3. Use the main button: Start, Send for review or Mark done on your own task; Accept and complete or Request changes on a review.
4. Add a comment on the task if something needs saying about that task.
5. Close the panel to return to the same list.

## A project's Work page
- id: projects-work-page
- area: projects
- status: published
- keywords: work page; what needs doing; next action; needs you; waiting on someone else; delivery summary; next milestone; site booking; equipment draft; import failed; waiting for warehouse; recent activity; project manager
- links: Projects -> /projects
- screens: /projects/[id]/work

Work is where a project starts. What needs doing is first: under Needs you are blockers you can clear, reviews, your overdue tasks and, for the Project Manager, overdue milestones and equipment decisions; under Waiting on someone else is everything that is another person's step. Each line shows its owner and due date, or says that none is recorded. The Project Manager also gets a delivery summary: next milestone, next site booking and equipment.

1. Open the project. Work is the first tab.
2. Read Needs you and open a line to go to that task or record.
3. For equipment, the Project Manager opens Equipment to review a draft and submit it; nothing is submitted for you.
4. If the line says Import failed, press Import the handover equipment to try again, or open Equipment.
5. Use Recent activity and Go to for the timeline, files, dependencies and site bookings.

## Project chat
- id: projects-chat
- area: projects
- status: published
- keywords: project chat; project discussion; discussion tab; message the project team; chat group; mention; unread messages; reply to the team; discussion moved to chat
- links: Projects -> /projects
- screens: /projects/[id]/work; /projects/[id]/discussion

Each project has one group in Chat, named by the project's reference and name. It replaces the Discussion tab: the earlier messages are in the group. Everyone on the project's team is in it and can read and reply from any page with the Chat button; people who are not on the team do not see it. Type @ to mention a team member: they see a red marker on the Chat button. A finished project's conversation can be read but not added to. Comments about one task stay on that task.

1. Press the Chat button at the corner of any page and choose the project under Projects.
2. Or open the project and press Chat in its header.
3. Write your message; type @ and choose a name to mention someone.
4. An old Discussion link opens the same group.

## Accept a Sales handover
- id: projects-handover
- area: projects
- status: published
- keywords: handover; accept handover; ask sales a question; clarification; delivery brief; project manager; assign project manager; new project from sales; handovers waiting
- links: Handovers -> /projects/handovers; My Work -> /projects/work
- screens: /projects/handovers

When Sales wins a job, the handover comes to Projects. Handovers waiting on you are listed first, the longest wait at the top, however many older finished ones there are. My Day opens the exact brief. The brief starts with the agreed scope, the site and dates, the equipment, the dependencies and risks, and any question you already asked Sales.

1. Open the handover from My Day, or open Handovers.
2. Read the brief.
3. Press Accept handover to create the project with you as Project Manager; it opens on the project's Work page.
4. Or press Ask Sales a question; the handover goes back to Sales and you are told when they resubmit.
5. If you press Accept twice, the same project opens: a second one is never created.

## The Projects page: every project you can open
- id: projects-list-overview
- area: projects
- status: published
- keywords: project directory; all projects; completed projects; archived projects; next milestone of a project; summary only; who is the project manager
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects

The Projects page lists every project you can see, with its Project Manager, status and key dates. Needs you at the top links to what waits for you across projects. A project you work on opens in full; any other project opens a short summary beside the list, because its plans, chat and files are for its team. The Next milestone column is filled only for projects you are part of.

1. Open Projects & Tasks, then Projects.
2. Type in the search box to find a project by name, reference or Project Manager.
3. Use Show to switch between Ongoing and Completed and archived, and Kind, Status or Company to narrow the list. Press Clear to remove the filters.
4. Click a column heading such as Key dates or Status to sort, or choose Board to see the ongoing projects by status.
5. Click a project to open it. All projects on the project brings you back to the same list.

## Start an internal project
- id: projects-new-internal
- area: projects
- status: published
- keywords: new internal project; create a project; add a project; internal project; accountable owner; project reference code; set code; ongoing work; showroom project; no client project
- links: Projects -> /projects; New internal project -> /projects/new
- screens: /projects/new; /projects

An internal project is for work with no client and no Sales enquiry, such as showroom technology or maintenance. Only a founder, or someone a founder allowed to assign Project Managers, can create one; everyone else does not see the button. The person you name as accountable owner becomes its Project Manager. Client projects are never created here: they start when a Project Manager accepts a Sales handover. Pressing Create project twice makes two projects, so press it once.

1. Open Projects and press New internal project.
2. Enter the Project name and choose the Accountable owner. With more than one company, choose the Company first.
3. Open Add more details if you want a Start date, End date, Ongoing work or a Brief.
4. If the form says the company has no project reference code yet, a founder sets it with Set code first.
5. Press Create project. The new project opens in Planning.

## Put a project on hold, resume it or reopen it
- id: projects-status
- area: projects
- status: published
- keywords: put a project on hold; hold a project; resume a project; review date; archive a project; reopen a project; edit project details; manage project
- links: Projects -> /projects
- screens: /projects; /projects/[id]/work

The Project Manager, a temporary project leader or a founder moves a project on, holds it or resumes it from Manage project in the project header. The Project Manager or a founder can also drag the project in the Projects card view. One step forward needs nothing more; going back or skipping a step needs a reason; a hold needs a reason and a review date. Completing has its own page, Complete project. Reopening a completed project is only for founders and people a founder allowed to reopen.

1. Open the project, press Manage project and choose Change status. Or on Projects choose Board and use Move to on the card.
2. Choose where it moves under Move to, fill in the Reason, or Why is it on hold? and Review date, and press Save status.
3. To bring a held project back, choose Resume: it returns to the stage it was held from.
4. To change the name, dates, location or priority, choose Manage project, then Edit details, and press Save details.
5. To reopen a completed project, choose Manage project, then Reopen project, say why, and press Reopen.

## The project calendar
- id: projects-calendar
- area: projects
- status: published
- keywords: project calendar; my calendar; company calendar; task deadlines; review requests; milestones; site bookings; month view; week view; agenda; time zone; project dates; project spans
- links: Calendar -> /projects/calendar; My Work -> /projects/work
- screens: /projects/calendar

Calendar has two views. My calendar shows your own task deadlines, the reviews waiting for you, the milestones of projects you are on and the site bookings made for you. Company calendar shows only each project's reference, name, status and start and end dates, never its tasks or bookings. Nothing can be changed here: click an entry to open the project and change it there. Deadlines are plain dates; timed site bookings show the site's own time first.

1. Open Projects & Tasks, then Calendar.
2. Choose My calendar or Company calendar.
3. Choose Month, Week or Agenda, and use the arrows or Today to move through time.
4. On My calendar, tick what to show under Show only, choose a zone under Show times in, and press Apply.
5. Click an entry to open its project.

## Add a task to a project
- id: projects-add-task
- area: projects
- status: published
- keywords: add task; new task; create a task; assign a task; give someone a task; needs review; depends on; collaborators; task for myself; who can assign tasks
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/work

Anyone on a project can add a task for themself from the project's Work page. A department head can also give tasks to the people in their team, and the Project Manager to anyone on the project. Three fields are enough: what needs doing, the assignee and the due date. The rest (department, deliverable, milestone, priority, review, dependencies, collaborators) is under Add more details. A person given a task by someone else is told.

1. Open Projects, choose the project and stay on Work.
2. Press Add task in the task list.
3. Fill in What needs doing, choose the Assignee and set Due.
4. Open Add more details only if needed. A department head or the Project Manager can tick Needs review so that someone else accepts the work.
5. Press Add task. It appears in the list as To do.

## Report or clear a blocker on a task
- id: projects-task-blocker
- area: projects
- status: published
- keywords: blocker; blocked; report a blocker; task is stuck; clear blocker; unblock; who can unblock; cannot mark done; waiting on someone; blocked task
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/work; /projects/[id]/work/tasks/[taskId]

When something stops a task, its assignee, the department head or the Project Manager reports a blocker on the task: what is in the way and who is responsible for unblocking it. That person is told, and the Project Manager is told as well when someone else is named. A blocked task shows Blocked in the list and cannot be marked done until the blocker is cleared. The assignee, the department head, the Project Manager or the named person can clear it.

1. Open the task from the project's Work page or from My Work.
2. Press Report a blocker.
3. Write What is blocking it and check Who is responsible for unblocking it (a person is suggested; change it if someone else can clear it).
4. Press Report blocker.
5. To clear it later, open the task, press More, choose Clear blocker, add a note if useful and press Clear blocker.

## Send a task for review and review it
- id: projects-task-review
- area: projects
- status: published
- keywords: send for review; ready for review; review a task; accept and complete; request changes; withdraw from review; waiting for your review; who reviews; needs review; sent back
- links: My Work -> /projects/work; Projects -> /projects
- screens: /projects/[id]/work; /projects/[id]/work/tasks/[taskId]

A task marked Needs review is finished by someone other than the person who did it: the head of its department or the Project Manager. The assignee starts it and sends it for review; the reviewer is told and accepts it or asks for changes with a reason; the assignee is told the result. Nobody reviews their own work. A task without Needs review is simply marked done by its owner. A blocked task cannot be accepted until the blocker is cleared.

1. Assignee: open the task, press Start, and when the work is finished press Send for review.
2. Reviewer: open the project's Work page and look under Waiting for your review, or open My Work, then press Review.
3. Press Accept and complete to finish the task.
4. Or press Request changes, write what needs changing and confirm. The task returns to In progress.
5. Assignee, before a decision: open Status on the task and choose Withdraw from review to take it back.

## Change a task's due date
- id: projects-task-due-date
- area: projects
- status: published
- keywords: change due date; move a deadline; new due date; reschedule a task; why is the date changing; dependent tasks; deadline changed; overdue task; postpone a task
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/work; /projects/[id]/work/tasks/[taskId]

The assignee, the department head or the Project Manager can change the due date of an open task. A reason is asked for and kept in the task's history with the old and new date. Nothing else is moved for you: if other tasks depend on this one and would now start before it finishes, they are listed so you can review them with their owners. When the assignee moves the date, the Project Manager and the department head are told; when one of them moves it, the assignee is told.

1. Open the project's Work page (or My Work) and find the task.
2. Press the pencil beside its due date, in the list or on the task.
3. Choose the new Due date and fill in Why is the date changing?
4. If dependent tasks are listed, read them and tick I have seen this and will review them.
5. Press Save due date.

## Milestones and deliverables
- id: projects-milestones-deliverables
- area: projects
- status: published
- keywords: milestone; add milestone; accept milestone; deliverable; add deliverable; department deliverable; change status; progress; required milestone; reopen milestone; manage milestones
- links: Projects -> /projects
- screens: /projects/[id]/work

Milestones are the points a project is accepted against; deliverables are pieces of work given to one department. The Project Manager adds and changes both. The head of the responsible department can update a deliverable's description, date and status and gives its work out as tasks. Progress counts accepted required milestones only. A milestone is accepted once its deliverables are closed, and a deliverable once its tasks are. Deferring, cancelling or reopening needs a reason.

1. Open the project's Work page and open Milestones & deliverables at the bottom (or press Manage milestones).
2. Project Manager: press Plan in the task list and choose Add milestone or Add deliverable; for a deliverable choose the Department team and the Milestone.
3. Press Edit to change one. A changed date asks why.
4. Press Change status, choose the New status, give the reason if asked and press Change status.
5. To accept, first close what belongs to it: a deliverable's tasks, a milestone's deliverables.

## The project timeline: Delivery and Site
- id: projects-timeline
- area: projects
- status: published
- keywords: timeline; project timeline; delivery timeline; site timeline; site production timeline; project plan; add timeline item; suggested stages; change a date; timeline bars; plan calendar; project calendar view
- links: Projects -> /projects; Project calendar -> /projects/calendar
- screens: /projects/[id]/plan

Timeline is the project's plan. Choose Delivery (the build) or Site (what happens on site) and show it as a List, a Calendar or a Timeline of bars; switching the view never changes a date. The Project Manager, a temporary project leader or a founder changes the plan; everyone else on the project reads it. Nothing reaches the client unless an item is ticked for the client timeline and a version is issued from Files & client plan. A finished project's plan is read-only.

1. Open the project and choose Timeline.
2. Choose Delivery or Site, then List, Calendar or Timeline.
3. On an empty plan press Create suggested stages to start from the suggestion, or press Add item.
4. In Add item fill What and choose When: Dates, Date and time at the site, or Not scheduled yet. Then press Add item.
5. Use Edit to change an item (give a reason when the dates change) or Delete to remove it. An item that a site booking uses cannot be deleted until the booking is cancelled.

## Book people on site
- id: projects-site-bookings
- area: projects
- status: published
- keywords: site booking; book someone on site; book a person; on site; double booking; overlap; conflict; check conflicts; confirm booking; tentative booking; cancel booking; travel time; preparation time; who can book
- links: Projects -> /projects; Project calendar -> /projects/calendar
- screens: /projects/[id]/plan

A site booking reserves one person at a site, in the site's own time, with preparation and travel time. The Project Manager books anyone on the project; a department head books the people of their own team. A booking starts as tentative. Confirming compares it with the person's confirmed site bookings on every project: an overlap stops it, unless a founder or someone a founder gave site-conflict authority to confirms it with a reason. The person is told when they are booked, changed or cancelled.

1. Open the project, choose Timeline, then Site.
2. Under Site bookings press Add booking. Choose Who is booked, the Site / location, the time zone of the site, Starts and Ends, then press Add booking (tentative).
3. Press Check conflicts to see the person's overlapping bookings. Projects you cannot see are only counted.
4. Press Confirm booking. If it is refused for an overlap, change the time or the person, or ask someone with site-conflict authority to use Confirm even if it overlaps (needs a reason).
5. Use Edit to change a booking (changing who, when or the travel time makes it tentative again) or Cancel booking to cancel it.

## Dependencies on others
- id: projects-dependencies
- area: projects
- status: published
- keywords: dependency; dependencies on others; waiting for; standbuilder; power and network; structure ready; site access; access permitted; confirm a dependency; not yet confirmed; expected date; responsible organisation
- links: Projects -> /projects
- screens: /projects/[id]/plan

Dependencies on others are things outside the team that must happen first: structure ready, power and network, access, the standbuilder's work. They are on the Site plan and are a record for the team only: nothing is sent to anyone. The Project Manager adds and updates them; everyone on the project can read them. A new dependency always starts as Not yet confirmed: set Confirmed or Not possible with Edit.

1. Open the project, choose Timeline, then Site.
2. Under Dependencies on others press Add dependency.
3. Fill What are you waiting for, choose the Kind, and add the Expected date and the Responsible organisation. Then press Add dependency.
4. When the other party confirms, press Edit, set Confirmation to Confirmed and press Save dependency.
5. Tick Offer this on the client timeline only if the client should see it in the next issued version.

## Files and the client plan
- id: projects-files-client-plan
- area: projects
- status: published
- keywords: project files; upload a file; add a link; documents; completion evidence; restricted file; remove a file; client timeline; client plan; issue the timeline; issue a new version; download pdf; record as sent; client acceptance; outdated timeline; out of date
- links: Projects -> /projects
- screens: /projects/[id]/documents

Files & client plan holds the project's files and links and the client timeline. Anyone on the project can add and open files and links, and remove what they added; the Project Manager can remove any. The client timeline shows only what was ticked for the client. Issuing freezes a numbered version and sends nothing; sent and accepted are recorded separately by the Project Manager. If the plan changes later, the latest version is marked Outdated until a new one is issued.

1. Open the project, press Manage project and choose Files & client plan.
2. To add a file choose Upload a file, pick the file, choose What is it and press Upload file. For a link choose Add a link and press Add link.
3. Project Manager: check What would be issued now, then press Issue this timeline (later, Issue a new version).
4. Press Download PDF and send it to the client yourself. Then press Record as sent and say how and to whom.
5. When the client agrees, press Record client acceptance and give the date and who accepted.

## Add or remove people on a project
- id: projects-people-access
- area: projects
- status: published
- keywords: add someone to a project; remove from project; project members; people and access; department team; department head; temporary leader; acting project manager; change project manager; who is on the project; sales link; project team
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/people

People & access lists everyone on a project, their role and their department team. The Project Manager, a temporary leader or a founder adds and removes people. Only people who already have Projects access can be added. A removed person loses the project's details, files, notices and Chat group straight away. The Project Manager and a department head cannot be removed until someone else takes that role.

1. Open the project, press Manage project and choose People & access.
2. To add someone, choose them under Add a person, pick a department if you want one, and press Add to project.
3. To remove someone, press Remove on their row, choose who takes over their open tasks if asked, and press Remove.
4. For a department, press Add department team, name it and choose its head; use Department on a row to move a person.
5. The Project Manager or a founder can hand over while away: under Temporary project leadership choose a member and a last day, then press Appoint. End now stops it early.

## Feedback and scope changes on a project
- id: projects-feedback-scope
- area: projects
- status: published
- keywords: project feedback; add feedback; correction; scope change; propose a scope change; approve scope; reject scope change; decide scope; withdraw proposal; change request; extra work
- links: Projects -> /projects; My Day -> /
- screens: /projects/[id]/changes; /projects/scope-decisions/[scopeChangeId]

Feedback & changes keeps what was asked for after the job was agreed, and every change to the agreed scope. The Project Manager adds feedback as a correction or as a proposed change. Something outside the agreed scope needs a scope change proposal, and only a person with scope approval can approve or reject it, with a reason. Approving replaces the current scope; the original stays on record. No date or cost moves by itself, and a chat message never approves anything.

1. Open the project, press Manage project and choose Feedback & changes.
2. Project Manager: press Record feedback, say who gave it, what was asked and whether it is a correction or a proposed change, then Save feedback.
3. The person responsible presses Update on the entry to set its status and say how it was resolved, declined or deferred.
4. Project Manager: press Propose a scope change, write the whole scope as it would read and the effect on dates, then Record proposal.
5. Scope approver: open the proposal from My Day or on this page, press Decide, choose Approve or Reject, give the reason and press Record decision.

## Complete a project
- id: projects-complete
- area: projects
- status: published
- keywords: complete project; close a project; finish project; completion; client confirmation; completion evidence; unfinished tasks; cancel or defer; completion note; signed handover; equipment still out
- links: Projects -> /projects
- screens: /projects/[id]/complete

Only the Project Manager, a temporary leader or a founder can complete a project. Nothing is marked done for you: every unfinished task, deliverable, milestone, piece of client feedback and upcoming site booking needs your decision and a reason. A client project also needs the client's confirmation. Completing does not return equipment: anything still out stays outstanding until the warehouse records its return. If the page says something could not load, press Retry; what you typed is kept.

1. Open the project, press Manage project and choose Complete project.
2. Under Unfinished work choose Cancel, Defer, Resolve or Decline for each item and write the reason. Apply to all sets a whole group at once.
3. For a client project choose the Kind of confirmation (E-mail reference, Signed handover or Uploaded confirmation), the date the client confirmed and who confirmed.
4. Write the completion note.
5. Press Complete project. The list under Before you can complete the project shows anything still missing.

## Project history and reopening a project
- id: projects-history-reopen
- area: projects
- status: published
- keywords: project history; change log; who changed the date; sales handover snapshot; completion record; reopen project; reopen a completed project; closed too early; what was agreed; history tab
- links: Projects -> /projects
- screens: /projects/[id]/history

History shows three things: the Sales handover as it was accepted, every completion with its evidence and the decisions taken, and the change log of dates, status, the Project Manager and people (the latest 100 changes). It is read-only. A founder, or someone a founder allowed to reopen projects, can reopen a finished project with a reason. The earlier completion stays in History, and anything cancelled or deferred at completion stays that way until the Project Manager reinstates it.

4. Write why it is being reopened and press Reopen. The project returns to In progress.
5. The Project Manager then reinstates the cancelled or deferred items that still matter.

## The Equipment tab of a project
- id: projects-equipment-request
- area: projects
- status: published
- keywords: equipment for a project; project equipment tab; equipment draft; imported from the sales handover; technology template; substitute; still out
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/equipment

The Project Manager asks the warehouse for equipment on the project's Equipment tab. A project that came from Sales starts with a draft marked Imported from the Sales handover. A request is a Draft until you press Submit to the warehouse; submitting sets nothing aside; the warehouse does that next. Then it reads Waiting for the warehouse, Being prepared, All dispatched and Closed. Other team members can read the tab but not change it.

## Dispatch and return notes on a project
- id: projects-equipment-notes
- area: projects
- status: published
- keywords: dispatch note; return checklist; return note; acknowledge; confirm this list; report a difference; dispatch waiting for you; returned please confirm; equipment still out; download PDF; equipment not returned; finished project equipment
- links: Projects -> /projects; My Work -> /projects/work
- screens: /projects/[id]/equipment

Where your company uses dispatch notes, each time the warehouse sends equipment to a project or receives it back, a numbered note appears under Dispatch & return notes on the Equipment tab. The Project Manager acknowledges it or reports a difference; nothing waits for the answer and no equipment moves because of it. Equipment still out lists what has not come back. Completing a project does not return equipment: only the warehouse records a return.

4. The warehouse answers it. Withdraw the report takes your report back.
5. Use Download PDF or Open to print for a copy of the note.

## From a won job to a finished project: who does what
- id: projects-won-job-to-finished
- area: projects
- status: published
- keywords: who does what; won job; handover to project; project workflow; next step; sales to projects; warehouse; dispatch; returns; complete project; start to finish; whose turn
- links: Handovers -> /projects/handovers; Projects -> /projects; My Work -> /projects/work; Requests -> /inventory/requests
- screens: /projects/handovers; /projects/[id]/work; /projects/[id]/equipment

A won job passes from Sales to a founder, to the Project Manager, to the warehouse and back. Sales submits the handover. A founder names the Project Manager, who accepts it: that creates the project and opens its Work page. The Project Manager adds the team, plans the tasks and submits the equipment request. The warehouse reserves, sends out and later records what came back. Completing the project does not return equipment.

1. Sales: confirm the enquiry as won, then prepare and submit the handover.
2. Founder: open Handovers and press Assign Project Manager.

## The Delivery plan of a project
- id: projects-delivery-plan
- area: projects
- status: published
- keywords: delivery plan; deliverables by zone; breakdown lines; release the plan; release work to the teams; delegate a section; accountable owner; raise a correction; proposed change to released work
- links: Projects -> /projects
- screens: /projects/[id]/delivery

The Delivery plan lists what the project delivers, zone by zone. Each deliverable has one accountable owner and a needed-by date, and only the breakdown it needs: Hardware, Content, Programming, Installation, Testing. Everyone on the project can read all of it. The Project Manager adds deliverables and releases the work; a person a section was delegated to fills in that section. Release creates the tasks and adds the hardware to the draft equipment request, once.

1. Open the project and choose the Delivery plan tab.
2. Project Manager: press Add deliverable, then Add line for each part it needs. Use Who defines each section to hand a section to Engineering, Content or Programming.
3. Project Manager: press Release plan. Tasks go to their people; hardware goes on the draft equipment request, which you still submit on the Equipment tab.
4. Anyone: press Correction on a deliverable or line if something is wrong. The lead decides and you see the decision under Decisions.
5. After release a change is a proposal: press Edit, then Propose change. The Project Manager approves or rejects it.

## Fill the Delivery plan from Excel
- id: projects-delivery-plan-excel
- area: projects
- status: published
- keywords: delivery plan excel; download template; import excel; export excel; delivery plan workbook; deliverables sheet; breakdown sheet; reimport the plan
- links: Projects -> /projects
- screens: /projects/[id]/delivery/import

You can prepare the Delivery plan in Excel. Download template gives a workbook with a Deliverables sheet and an optional Breakdown sheet; a simple job needs only Deliverables. Export Excel gives the current plan with its IDs, so you can edit and import it again without making duplicates. Importing shows a preview first and saves nothing until you confirm. Blank cells and missing rows never delete anything, and importing never releases work.

1. On the Delivery plan press Download template, or Export Excel to edit the current plan.
2. Fill one row per deliverable. Keep the ID columns as they are; leave them empty for new rows.
3. Press Import Excel and upload the file. Read the preview: Add, Update, Unchanged, Needs attention.
4. Answer anything under Needs attention, such as a name that matches two people, then press Import.
5. Back on the Delivery plan, the Project Manager presses Release plan when the work should go to the teams.

## The closeout report of a project
- id: projects-closeout-report
- area: projects
- status: published
- keywords: closeout report; generate closeout report; project closeout; review data to be sent; facts-only draft; approve the report; download the closeout report; lessons for the next project; client sign-off not recorded
- links: Projects -> /projects
- screens: /projects/[id]/closeout

The closeout report is an internal report about one project, prepared by its Project Manager from the project's own records. You first see exactly what would be used; written text such as scope wording and client words is left out unless you tick it. Writing with the AI model sends only that reviewed content to Anthropic; a facts-only draft sends nothing. The report always states recorded facts such as client sign-off and equipment still out. Nothing goes to the client, and the project is not completed by it.

1. Open the project, press Manage project and choose Closeout report.
2. Read Review data to be sent. Tick only the written text you want included.
3. Press Send to Anthropic and write the draft, or Write a facts-only draft.
4. Check each paragraph against its sources, edit it, then press Save edits.
5. Press Approve version, then Download PDF on the approved version.
